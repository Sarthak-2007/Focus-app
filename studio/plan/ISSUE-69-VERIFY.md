## (b) Fix specs

### §b-1 — F1 (Prisma cures): shield loop — kill the duplicate scan, the unconditional notify, and cache the blocked set
- **Files:** `service/MonolithShieldService.kt` only (stage A); no repo change.
- **Exact change:** (1) Delete the second scan at `:180` — build `val appsByPackage = <first snapshot>.associateBy{it.packageName}` from the `:165` list and look the intercepted app up in that map (the `:165` snapshot is ≤2 s old; the app row cannot meaningfully change inside one iteration). (2) Notify-on-change: keep `private var lastNotifiedSubtitle: String?` in the loop; call `updateNotification` only when the composed `subtitle` differs (urges-blocked count is in the subtitle, so a block still re-notifies instantly; the minute display changes ≤1/min). (3) Blocked-set cache: recompute `blockedPackages` from a fresh `getAllAppsSnapshot()` only every 15 iterations (30 s, aligned with the existing heartbeat cadence at `:91`) or when `WatchStore` pokes — between refreshes reuse the cached set. The peek-lease expiry inside the filter uses `nowMono`, so the *filter predicates* must still be re-evaluated per iteration over the cached rows — cache the rows, not the resulting set.
- **Preserves:** 2 s cadence, `stampShieldBeat=true` every iteration (the 10 s shield-gap law at `SHIELD_GAP_THRESHOLD_MILLIS` depends on the beat — do **not** slow this loop in this fix; the write cut belongs to §b-3), UsageStats detection latency unchanged.
- **Risk:** Low. Stale-tier window grows from 0 s to ≤30 s for a tier changed *outside* a session flow (in-session tier changes already route through the VM/DB and a 30 s worst case matches the heartbeat's existing reconciliation promise). **Price:** ~25 lines, one file, no schema, no test-shape change; add/extend a unit test only if a pure `shouldNotify(old,new)` helper is extracted (recommended, 5 lines).

### §b-3 — F3 (Prisma cures): single lawful writer — VM ticker stops persisting progress
- **Files:** `ui/MonolithViewModel.kt:967-974` (delete one call); optionally a guard, below.

Keep `:972 latchShieldGapIfStale(...)` (it is the gap *evidence* latch, not progress), keep `_themeNow`, peek-pill derivation and warrant refresh — all read-only.
