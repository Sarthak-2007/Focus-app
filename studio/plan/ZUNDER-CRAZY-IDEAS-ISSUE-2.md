## ZUNDER — CRAZY IDEAS for #2: don't just fix the call-sites, make drift IMPOSSIBLE, LOUD, and SELF-HEALING

Read the cell plan (`ISSUE-2-test-call-sites.md`) first. The disease is named correctly: **lane-generation drift** — production `ParkDrawer` gained 4 required params across two generations, tests froze in theirs, plus one SDK-36 constructor arity break and two phantom imports. Fixing the 6 sites cures today's patient. These ideas cure the *disease*. Every idea is buildable with what's already in the tree (JUnit, Compose UI test, Robolectric, GitHub Actions `rescue-build.yml`). No production defaults added — §1's scope discipline holds throughout.

### 1. THE ONE DOOR — a single test-side factory every `ParkDrawer(` call must go through
Today: 5 call-sites, each hand-listing ~15 args, each drifting independently. Replace all 5 with ONE call: `renderParkDrawer(ParkDrawerTestArgs())` in a new `app/src/test/.../ParkDrawerTestFactory.kt`, where `ParkDrawerTestArgs` is a data class with a neutral default for *every* parameter, and each test overrides only the pair it actually studies (`ShortsToggleRenderTest` overrides the shorts pair with `storedShorts`; `SoundAndSocialTruthTest` overrides the social pair; the other three override nothing). Next time production gains a required param, exactly **one file** fails to compile and exactly **one line** fixes the whole suite. Drift surface: 5 sites → 1. Cost: ~80 lines + touching the 5 sites once. This is the single highest-leverage move on this issue — do it *while* fixing the sites, the edits are the same edits.

### 2. THE DRIFT ALARM — a plain-text census test that needs NO compilation to catch drift
The cruel joke of Class A–E: you only learn about drift when the source set *fails to compile*, which also kills the messenger (no test can run to explain it). So write the census as a **standalone script, not a Kotlin test**: `studio/tools/census_callsites.py` (~120 lines, stdlib only) that parses `ParkDrawer.kt`'s parameter list with a regex/brace-counter, greps every `ParkDrawer(` in `src/test`, diffs named args, and prints the §2 census table automatically — file, site line, missing pair, generation guess. Wire it into `rescue-build.yml` as a job that runs *before* Gradle (30 seconds, no JDK). A future drift then arrives as a readable table on the PR, not a Kotlin error avalanche. It would have generated this issue's §2 in one run.

### 3. SIGNATURE FINGERPRINT — make the compiler's first error a human sentence
Add `ParkDrawerSignatureTest`: a reflection-free, source-level guard is impossible inside a non-compiling suite (see #2), so instead pin the *contract as data*: a checked-in `parkdrawer-contract.txt` (param names + types, one per line, in order). The Drift Alarm (#2) diffs production against this file too. When they differ, CI posts: *"ParkDrawer gained `foo: Boolean` (required, no default) on <date>. Test factory default needed: see ParkDrawerTestFactory.kt."* — the fix instructions inside the failure. Fingerprint updates become a deliberate, reviewed act: changing production's contract without updating the fingerprint is itself a red CI job.

### 4. NEUTRALITY PROOF — stop *hoping* `true / {}` scaffolding is neutral (kills Risk 3 by experiment)
The plan's Risk 3 admits the neutral values might not be neutral and says "re-derive if a test goes red." Wilder and better: **prove neutrality now** with a dedicated test class `ScaffoldingNeutralityTest` that renders `ParkDrawer` via the factory (#1) with the shorts pair and social pair in all **4 combinations** (off/off, off/on, on/off, on/on) and asserts the *unrelated* printed surface (the YPT line, the routines line — the exact strings `TruthCar3SweepTest` asserts) is byte-identical across all 4, except the toggles' own rows. If a combination changes an unrelated word, neutrality is false *for that word* and we learn it from a designed experiment, not from a mysterious red suite after merge. 4 renders, ~60 lines, Robolectric/Compose test as the sweep already uses.

### 5. THE TOGGLE MATRIX — screenshot goldens for all 16 states, not the 2 somebody happened to render
`ScreenshotHarnessTest` renders PARK once. Extend it into a **state-matrix harness**: shorts × social × (one more binary state already in the drawer) × light/dark of the current look = 16 golden captures, named by state (`park_shortsON_socialOFF.png`…), stored as test resources with a tolerance diff. Any future param that changes the drawer's face shows up as a *named picture diff* in CI instead of a word-assertion lottery. This also hands the design lanes a free visual census of the drawer in every state — they currently design against single-state renders.

### 6. PLATFORM TIME-CAPSULE — an arity sentinel for every hand-built Android class, not just `StatusBarNotification`
D-1 was fixed by inserting a bare `0` and a brave comment. Generalise: a test-side factory `TestNotifications.statusBar(...)` (named args internally, one construction site for the whole suite — same One Door trick as #1) **plus** a sentinel unit test that reflectively asserts `StatusBarNotification::class.java.constructors.maxOf { it.parameterCount } == 10` with a failure message that says *"SDK moved: update TestNotifications and re-check the score argument's meaning before touching the number."* Next SDK bump: one red sentinel with instructions, one factory edit — instead of a positional-argument riddle buried in a capture test. Apply the same factory pattern to any other hand-constructed framework class the sweep grep finds.

### 7. THE PHANTOM-IMPORT HUNT, SETTLED FOREVER — an import census in the Drift Alarm
E-1/E-2 burned real cell time: are `assertExists`/`assertDoesNotExist` top-level or `SemanticsNodeInteraction` members in Compose BOM 2024.09.00? Don't let the next cell re-litigate this class of question. The Drift Alarm script (#2) gains a mode: for every `androidx.compose.ui.test.*` import in the test tree, check it against the actual AAR/classes.jar of the pinned BOM (downloaded once in CI, cached) — resolvable top-level, member-function (import unnecessary *and* harmful if unresolvable), or absent. Output one line per import with the verdict. The E-question becomes a 1-line lookup, permanently, for every future import dispute in this suite.

### 8. FIRE DRILLS — scheduled synthetic drift to measure whether any of this actually works
Once #1–#3 land, prove them the adversarial way: a monthly scheduled Actions workflow (`drift-drill.yml`) that, on a throwaway branch, adds a dummy required param `drillProbe: Boolean` to `ParkDrawer`, pushes, and checks: (a) Drift Alarm job goes red with the readable table, (b) exactly one compile error location exists (the factory), (c) time-to-diagnosis is just the CI log. If the drill ever produces an error avalanche, the defences have rotted and we find out from a drill, not from batch-12. Nobody merges the drill branch; it auto-deletes. Cost: ~40 lines of YAML + a script that applies/reverts the probe patch.

### 9. GENERATION TAGS — every test file declares the generation it was written against
Cheap, weird, effective: a header convention `// parkdrawer-gen: social+shorts` (and equivalents for other multi-generation composables) in each render test, maintained by the factory adoption in #1. The Drift Alarm cross-checks tag vs. actual args; a mismatch means a half-migrated file — exactly the B-1 shape (social real, shorts missing) that pure arg-diffing catches but a human reviewer reads straight past. Tags make the suite's archaeology visible at `grep` speed: `grep -L "gen:" src/test/*.kt` = un-migrated files, forever.

### 10. THE SECOND CENSUS, AUTOMATED — treat the first green compile as a data source, not a finish line
Risk 2 says errors may hide behind the six known sites. When the gate compile finally runs, don't just read pass/fail: harvest the full error list into the census format (the Alarm's table), auto-append any new site as a new lettered class on this issue via a CI-posted comment, and keep the issue open until a compile completes with **zero** errors *and* the Alarm agrees zero is real (script-vs-compiler cross-check). Two independent censuses agreeing = the census is actually complete, which no single pass can ever claim.

**My ranking if the cell takes only three:** #1 (One Door — kills the disease structurally), #2 (Drift Alarm — catches what #1 can't, in plain language, pre-compile), #4 (Neutrality Proof — converts the plan's admitted guess into a proved fact). #1+#2 together cost less than the cell time E-1/E-2 already burned.
