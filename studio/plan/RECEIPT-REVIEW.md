## CHARGES

### RC-01 (S2) — ENDED prints a derivation as a fact on two of the three paths that can issue a slip

The sheet prints `ENDED ${hhmm(receipt.endedAtWallMs)}` with no distinction between paths (ReceiptSheet.kt:124–126). Only one path supplies a true end:

- **Witnessed path (exact):** the finish controller's collector sees the finish emission live; E0 is that frame (MonolithViewModel.kt:1024–1025) and the span elapsed within a tick of it. ENDED is honest here.
- **Branch U (derived):** a finish *first sighted* up to 10 minutes after its derived end is published at discovery — `ageMs <= 600_000L -> onFinishE0(row, kind, witnessed = false)` (MonolithViewModel.kt:1004–1007) — and `onFinishE0` stamps `e0Wall = System.currentTimeMillis()`, the *discovery* instant, which flows into the slip as `endedAtWallMs` (MonolithViewModel.kt:1025, :1038, :1047). A session that ended nine minutes before the app restarted gets a slip reading ENDED = the restart minute. The code names this bound internally ("E0 := discovery", MonolithViewModel.kt:~978) — the slip does not carry the name.
- **Rehydration (derived):** the standing slip after a relaunch rebuilds `endedAt` for manual rows as `startWall + (lastTickMono − startMono)` (MonolithRepository.kt:1641–1647). The function's own KDoc concedes "the true E0 wall was never persisted" and calls this "the rehydration approximation" (MonolithRepository.kt:1619–1626). Where the process died before the finish was witnessed, the last tick is a recovery-era tick and ENDED can read as the relaunch time.

Same typeface, same precision, three different epistemic classes. **Fix shape:** persist the E0 wall on the row at the ending write (one column, stamped by finalise) and let all three paths read it; until then the derived paths should not print a minute they did not witness.

### RC-02 (S2) — PLANNED on a FLOW receipt prints the stopwatch floor through the block formula and calls it a plan

Assembly sets `plannedSeconds = row.spanTargetSeconds` for every kind (MonolithRepository.kt:1501). For a stopwatch row the target is not a plan at all: `targetSecs = STOPWATCH_MIN_FLOOR_SECONDS` = 1200 (MonolithRepository.kt:1227–1232, :96), and `spanTargetSeconds = totalStudyBlocks × effectiveTargetSeconds + (blocks − 1) × 600` (MonolithModels.kt:367–369). The arm path passes the Deck's block count through untouched for stopwatch arms (ArmProvingController.kt:179–184, :345–349). So every FLOW slip prints `PLANNED 20 MIN` at one block — the *floor*, mislabelled — and up to `PLANNED 3H 50M` at eight blocks, a span no FLOW session ever had: FLOW has no blocks and no plan; it ends when he ends it past the floor. The one true span the session lived, `sealedElapsedSeconds`, is gathered into the state (ReceiptState.kt:138, :166) and printed *nowhere* on the slip (grep: ReceiptSheet.kt references it zero times), so the slip offers no true figure to set against the false plan. **Fix shape:** FLOW_FINISH slips omit the PLANNED segment — the same omission law the HELD line already obeys when its fact is uncaptured (ReceiptSheet.kt:129–133).

### RC-03 (S2) — A restored slip's WITHIN line (hand-armed rows) is re-derived from live routine definitions, so post-finish edits rewrite a standing receipt

For routine rows the label is frozen from row stamps (MonolithRepository.kt:1446–1453) — correct. For hand-armed rows it is evaluated at assembly time against the *current* routine table: `routineWindowLabelAt(row.startWallTimeMillis)` reads `dao.getAllRoutinesSnapshot().filter { it.enabled }` and matches current name, days mask, and window minutes (MonolithRepository.kt:1525–1553). Rehydration re-runs the same assembly (MonolithRepository.kt:1650). Consequence: rename a routine, retime it, or disable it after a finish, and the *restored* slip for that finish prints a different WITHIN line — or none — from the slip he was actually issued. The issued slip and its own restoration can disagree, and nothing on either says so. This sharpens tonight: the routine-edit car (batch 8, in flight) ships rename and retiming to his hands, making the rewrite reachable by the user himself, not just by drift. **Fix shape:** freeze the label onto the row at issuance (the routine-row path already proves the pattern), and let rehydration read the frozen copy.

### RC-04 (S3) — The № latch is single-slot; one session holding two №s across time is forbidden by arithmetic, not by the latch

The claim returns the standing № only when `lastReceiptSessionId == sessionId` (MonolithRepository.kt:1391); the publish once-gate likewise compares only against the *latest* standing receipt, `standingReceipt()?.second == pending.sessionId` (MonolithRepository.kt:1575). If session A (№5) were ever re-published after session B (№6) claimed, both guards pass and A mints №7 — the same finish wearing two numbers, and its restored slip would show the second. I could not make it fire: re-publication can only arrive via branch U's 600_000 ms first-sighting window (MonolithViewModel.kt:1006), and every intervening publishable span is ≥ 600 s (timed dial ≥ 10 min; FLOW floor 20 min; routine windows ≥ 30 min), so A's age at any such restart already exceeds the window. The invariant holds — as a coincidence of two constants in two files (600_000 in the VM, the span floors in the Repository). **Fix shape:** stamp the claimed № on the session row inside the claim transaction and latch on the row, so the guarantee survives any future change to either constant.

## OBSERVATIONS (filed, not charged — no false print)

- **O-1 — The gap fact prints twice.** On a shield-gap slip the ENDED line reads `ENDED · SHIELD GAP` and the bold line below reads `THE SHIELD WAS OFF FOR PART OF THAT SESSION` (ReceiptSheet.kt:125, :138–146; word from MonolithRepository.kt:1562). Render proof: shots/09_receipt_shield_gap.png shows both. Redundant, not false — but the slip's discipline elsewhere is one fact, one line.
- **O-2 — BREAK BANKED cannot print today.** The slip's branch exists (ReceiptSheet.kt:134–138) and the field is summed from the spend ledger at assembly (MonolithRepository.kt:1463–1472), but the ledger's only write is the completed valve break (MonolithRepository.kt:1948–1979), which disarms `completed = false` → VALVE_BROKE → never a finish (ReceiptState.kt:100–113). Banks and abandoned holds write nothing (§4.3, stated at MonolithRepository.kt:1946–1947). So the figure on every publishable receipt is 0 and the line is dormant — the assembly comment admits this itself. Not a lie; a loaded field. Its future honesty is arithmetic-safe: the one spend constant is a flat 60 (MonolithRepository.kt:108), so any future `n MIN` print stays exact under the `/60` at ReceiptSheet.kt:136.
- **O-3 — The detention publish gate can swallow a finish silently.** If the terminal predicate no longer admits the row at issue time, `publishReceipt` returns null (MonolithRepository.kt:1568–1575), the finish state still marks `issued = true` with `receiptNumber = null` (MonolithViewModel.kt:1113–1117), and `handledFinishIds` keeps the session handled — that finish never gets a receipt, ever. No false print occurs (that is the gate's purpose), and the № sequence stays gapless because the claim never ran. Filed so the behaviour is a known price, not a discovered one.
- **O-4 — Only the latest receipt can ever be re-shown.** One slot (guard_settings: № + pointer + outcome word, ReceiptState.kt:11–19); rehydration rebuilds only the standing slip (MonolithRepository.kt:1629). Every older № is a number without a surface. By Z1's design — named here because a man flipping back for yesterday's slip will not find one, and that absence should be a decision on record, which it now is.
- **O-5 — ARMED prints the seal instant, not the tap instant.** `armWallMs = row.startWallTimeMillis` (MonolithRepository.kt:1498), and the seal re-anchors that field to t=0 and re-signs it (MonolithRepository.kt:1308–1330). The printed minute is the proven start — the anchor the HMAC itself verifies — which is the honest reading of "armed"; named so nobody later "fixes" it to the tap.

RC-02 is the stopwatch exception, charged there.
10. **Title** — `row.intention`, frozen at insert with a non-blank default substituted at birth (MonolithRepository.kt:1247, :1497). It is what he declared, and nothing rewrites it.
