## Addendum (Sten's handoff, post-merge — read with §05)

Sten's formal handoff added four load-bearing facts the digests above
only imply. They bind the routines build:

1. **Lie #13 — ghost booking at the source.** Verified in code: the
   receiver starts a full-duration session at START and
   `disarmActiveSession(completed=true)` books wall-clock elapsed. An
   untouched phone earns a completed 3H block (plus a Curio artifact).
   The no-ghost fix therefore lives at *disarm time*, rewriting/zeroing
   the session at END from evidenced presence — not at display time.
   `compute7DayHistory` becomes truthful with no change of its own,
   because elapsed is made true at the source.
2. **DB v8 precondition — destructive fallback.** The database is built
   with `fallbackToDestructiveMigration(true)`: shipping DB 8 without an
   explicit `Migration(7, 8)` would wipe the very rows the reseed exists
   to migrate. The explicit migration is a precondition, not a detail.
3. **Rename fence.** The receiver's END matches sessions by
   `profileName == "Routine: <name>"` — renaming a routine inside an open
   window orphans its session. Rename is fenced until session matching
   moves to ids (Sten §3/§5).
4. **Span clamp unified 30..1080** in both `adjustRoutineTime` and
   `durationMinutes` (Reihe's catch: the two disagreed — the row would
   have printed one length and run another; DAY BLOCKS is 630 minutes).
   Also: attendance gains a sixth outcome, NOT_DELIVERED (streak-neutral,
   like LATE_FIRE); theme precedence is session → SLEEP window → day,
   applied as a silent 0ms cut evaluated from clock+DB, never from alarm
   delivery; Yuki's throw contract is adopted wholesale for the mini-sled
   with one recorded deviation — tap = toggle on the sled itself.
