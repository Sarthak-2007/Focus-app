# §1 — THE VOCABULARY

## 1.0 Rules of the list

1. **One name per thing, everywhere** — nav stop, screen title, chrome, speech,
   notifications: the same string. A thing with two printed names is two things
   to a tired man at 03:30.
2. **One word, one meaning.** A word that means two things in two places is
   banned in both until it means one. (The two deliberate families — OPEN,
   HELD — are defined once in §1.4 and their unity is the definition.)
3. **Screens are parts, not processes.** A destination is named for the object
   he finds there (a deck, a shield, a list of tasks), never for an activity,
   a mood, or a promise (focus, horizon, runs-itself).
4. **Case.** Printed app words are UPPERCASE in plate and label roles; state
   words always UPPERCASE; sentences (the overlay's one human line, the
   receipt) are sentence case in Atkinson. His words keep his case.
5. **The list is closed.** A new printed word enters only by amending this
   file with Sana's sign-off, and the default trade is one-in, one-out. A
   feature that needs a word the list refuses does not get the word — it gets
   redesigned, or it dies.

## 1.1 Screen names — the survivors

| **SHIELD** | SYSTEM, SUITCASE | SYSTEM is the operating system's word — generic, and it drags "system settings / system permissions" SaaS language behind it. SUITCASE (the nav's current word for this screen) is a second metaphor for the screen's contents and names neither. SHIELD is the job: the thing that stands shut between him and the apps. Code name and printed name finally agree. |
| **TASKS** | HORIZON | HORIZON is poetry for a queue — and the queue's own header ("WORKLOAD HORIZON") proves poetry breeds more poetry. TASKS is what is on the screen. Nothing else is. |
| **LEDGER** | VAULT | VAULT is a secrecy metaphor (a safe, a Silence Vault) for what is only a record book; it was also never the printed word — the nav already said LEDGER while code and half the swarm said Vault. LEDGER is the honest object: a book of entries. *Conditional:* this names the record wherever it lives — as a tab (D-A keep) or as the Shield-foot section (demote). Code names follow the printed names when next touched (Vault → Ledger);
until then code names are internal and never leak to a surface.

**Loadout contents, same law applied one level down:** the preset sets of app
states are **LOADOUT 01 / 02 / 03 — STUDY / DEEP / SLEEP**. SUITCASE and BAG
are banned as printed words for them (two travelling-case metaphors for one
object, and SUITCASE was doing double duty as a screen name). A loadout's
number is its position on the strip, not a second name; its name is STUDY,
DEEP or SLEEP, in his words thereafter.

**Routines are named by their name only.** The wave-1 `PRG 01` numbering dies:
a number beside a name is a second name, and the meta line already carries the
facts that matter (`MON–FRI · STUDY · 4H 00M` — days · loadout · duration).
Task `#01 / #02` survives for the opposite reason: queue numbers are
*positions*, they change as the queue moves, they name nothing.

## 1.3 Verbs — the closed list (12)

Every tappable or gestured act in the app is one of these. A control whose
act is not on this list does not ship.

| Verb | The one act it names | Where it may print |
|---|---|---|
| **ARM** | Commit a session to start now, from the Deck's set state | The slide only: label `SLIDE TO ARM`. Never on a cap, a sled, a routine row, or Guard — wave-1 spent ARM on three different acts and the word stopped meaning the commit. |
| **START** | Commit a session from a task — the task becomes the session's task | Tasks, on the ACTIVE task only. Its COMMIT fill is Tasks' one orange. ARM and START are different acts (from the wheel's state / from a task) and never substitute. |
| **DONE** | Mark a task or a step finished | Tasks rows; the Deck NOW line (idle only — HOLD removes it mid-session). |
| **ADD** | Put a new task in the queue / a new site in the site list | Composer key; site-list add. The only creation verb. |
| **CUT** | Remove a task or a site, permanently | Tasks rows; site list. Replaces DEL, DELETE, REMOVE — three SaaS verbs for one act, all dead. |
| **QUEUE** | Send the NOW task back and bring the next forward, marking nothing done | Deck NOW line, idle only. (QUEUE is also the queue's label-noun, §1.2 — same object, not a second meaning.) |
| **PEEK** | Request the one permitted opening of a SHUT app: 2 minutes, then SHUT again | The blocked-app overlay only. Everywhere else PEEK is a state word (§1.4), never an action. |
| **HOLD** | Keep a finger down on the break control for the full banked minute | The hold overlay: instruction `HOLD TO BREAK`. Also the mechanism's name (the HOLD; HOLD SPENT). Never a synonym for a session (a session is not "a hold"). |
| **BREAK** | End the running session early, spending the week's one break | The hold overlay's outcome word; the receipt of a broken session (`BROKEN AT 31 MIN · HOLD SPENT`). |
| **FIND** | Search a list already on the screen | Field placeholders only: `FIND AN APP`, `FIND A SITE`. Replaces FILTER and SEARCH — one verb, and it promises finding, not filtering machinery. |
| **FIX** | Leave the app to the one Android settings pane that grants what is missing | Guard only (§3.4), and the G-DISSOLVED drawer's permission rows. The only verb that leaves the product — which is why it is ink, never orange: it commits nothing in here. |
| **KEEP** | Decline a CUT in a confirmation dialog | Dialogs only. The negative half of CUT; prints nowhere else. |

Explicitly *not* verbs, whatever the old renders say: SHUT / PEEK / OPEN on a
sled are **states the sled is set to**, set by travel, not buttons that
"shut" things; ON / OFF / PAUSED are states (§1.4). There is no SAVE (the
composer and the routine editor commit on their one verb and print the result
as its future list line), no EDIT button-word (a row opens its editor by being
the row), no REFRESH (state re-reads itself; a button that re-asks the OS is
an admission printed as a feature — `REFRESH SYSTEM PERMISSIONS` dies first).

## 1.6 Fixed phrases and formats (the only sentences allowed)

- **War line:** `186D TO NEET · TODAY 2H30 / 12H` (Razor owns geometry;
  the words and the stale-segment omission are fixed here).
- **NEXT ribbon:** `NEXT 09:00 · STUDY` — time · loadout. Nothing after the
  loadout name: `FIRES ITSELF` and every cousin are narration, banned §1.7.
- **Receipt (one line, one showing):** `SEALED 50 MIN · STUDY · 3 DEFLECTED`
  / `BROKEN AT 31 MIN · HOLD SPENT`. The word **DEFLECTED** lives here and
  in the Ledger meta line only: it counts blocked attempts during a session,
  and it is a participle in a receipt, never a tile, never a score.
- **Routine meta:** `MON–FRI · STUDY · 4H 00M` (days · loadout · duration).
- **Window line:** `WINDOW OPEN — ENDS 03:30`.
- **Empty states** (the complete set): `NO TASKS` · `NO SITES` · `NO RECEIPTS`.
  Absence is otherwise rendered as absence — no sentence explains an empty
  list, and no empty state may encourage, apologise, or instruct beyond §1.3.
- **Formats:** times 24-hour, always (`09:00`, `FINISHES 17:32` — AM/PM is
  banned as a second format for the same fact); durations `25M`, `2H30`,
  `4H 00M` in meta; positions two-digit (`01`), counts unpadded; the queue
  total and the readout are bare numbers whose unit lives in their caption.

# §2 — THE VERB-CODE LEGEND, AS IT PRINTS ONCE AT THE FOOT OF SHIELD

The code is used most densely where the sleds are — so the key is printed
there, once, and nowhere else in the working app. (The Guard plate, §3.5,
carries the code as one *spec line* among its factory lines, without swatches:
that is the machine's specification of itself, not a second key. If a future
ruling kills one of the two, the Shield key survives — a code is explained
where it is worked, and the plate is amended, §1.0.5.)

**Exact printed line** (one line, no wrapping, this order, this punctuation):

```
■ ORANGE = COMMIT · ■ INK = SHUT · ■ GREY = PEEK · ■ PORCELAIN = OPEN
```

- **Order rationale:** COMMIT first — the exception before the rule, the one
  orange thing in the app named before the three sled states; then the sled
  states in their own left-to-right travel order: SHUT · PEEK · OPEN.
- **The swatches** are specimens, not accents: 8×8dp squares, radius 0 (they
  are ink chips, not keys — the 8/16 radius law governs components, and a
  legend chip that looks tappable is a lie), filled with the exact tone each
  word names — orange `#F55314` (night: glyph register `#F47442`, the only
  orange legible as print at 8dp on the night ground) · ink `#252323`
  (night: control fill `#4A423C` with the word INK unchanged — the tone's
  *role* is ink) · grey `#615B5A` both modes · porcelain `#FAF6F0` (night
  `#332A27`) with a 1dp hairline in the current outline token, because a
  porcelain chip on either ground is otherwise an empty square — the outline
  is print registration, not a border on a component.
- **Type:** the plate — Anonymous Pro Bold 10sp, tracking +2.0, lineHeight
  12sp (Set's locked micro-label plate; "footer legend" is named in her ramp
  under exactly this style). All five words in the secondary ink tone (day
  `#5F5856`, night text tier 2) — the line explains colour; it does not wear
  it. No word in the line is ever set in the colour it names, and the `=`
  and `·` are the line's only punctuation.
- **Geometry:** left edge on the 20dp margin; first swatch's left edge on the
  margin, 6dp swatch-to-word, entries separated by the printed `·` with the
  tracking's natural space — no extra spacers, the line is set as one string
  with three inline chips. Top: 16dp below the last APPS row's baseline zone
  (i.e. directly under the final hairline of the apps list). Bottom: if the
  LEDGER section ships at Shield's foot, the settled 48dp section break
  follows the legend and nothing may be inserted between them; if not, the
  legend is the last printed thing above the bottom scroll inset.
- **Discipline:** appears on Shield only; never repeated on Deck, Tasks,
  Ledger, a dialog, or the AOD; never state-dependent (it prints identically
  whether zero apps or twelve are SHUT); never tappable, never animated.
  A code you must re-explain on every face is not a code — and a key that
  changes with state is not a key, it is another readout.

**Acceptance check:** cover the Shield screenshot's sleds — the line still
reads as a complete key. Search the build for the string `= COMMIT`: exactly
one hit in the working screens (the plate's spec line, §3.5, is the second
and only other permitted hit, and it carries no swatches).

# §3 — G-KEPT: GUARD IS THE PRODUCT'S BACK

*Branch condition: Sarthak keeps Guard as a destination. If he dissolves it,
this section is void except §3.5's plate text, which migrates to the foot of
the drawer as print, unaltered.*

## 3.1 The idea, in one paragraph

A real instrument has a back: the panel the manufacturer prints the
specification on, the place you turn the object over to when something is
wrong. Guard in this branch is that back. It is not where the app is *used* —
nothing is aimed, queued, or armed here. It is where the machine states, in
print, what it is, what state its organs are in, and exactly one thing he can
do about the one class of problem that is his to fix (a permission the OS
withholds). Everything on the screen is printed matter except a single line.
A Guard that grows a second interactive element has stopped being a back and
become a settings page; §3.6 is the discipline that prevents it.

## 3.2 Screen composition (top to bottom, exhaustive)

1. **War line** — shared chrome, unchanged. (The model mark does *not* join
   it: `MONOLITH ML-01` prints once, on this screen's plate, §3.5 — Razor's
   §0.2 assignment, which this section honours.)
2. **Band switch** — gains the fourth stop `GUARD` (with the Ledger tab kept:
   five stops is forbidden; G-KEPT pairs with the Ledger demote, or the rail
   formula re-opens — that arithmetic is Razor's, flagged in §4. In the
   demote pairing the stops are DECK · SHIELD · TASKS · GUARD.)
3. **Eyebrow** `STATUS` (plate style), 32dp below the war line's band.
4. **The status board** (§3.3) — printed rows, no controls.
5. **The FIX line** (§3.4) — present only when the board shows a lack;
   otherwise absent, and the space closes up: absence renders as absence.
6. **32dp section break, one hairline, the spec plate** (§3.5) — the last
   thing on the screen. Nothing below the plate except the scroll inset and
   the band switch. The plate is the bottom edge of the product's back, the
   way print runs to the edge of a real back panel.

## 3.3 The status board — status as printed matter

**Form:** ruled lines, not rows. Each line: name in the plate style
(Anonymous Pro Bold 10sp, +2.0) left on the margin; the state word at the
right margin in the body tier (Atkinson Bold 15sp, +0.5 — Set's ruling:
a word that carries a state is truth, and truth is never whispered at plate
size). 1dp hairlines between lines at ink 18%. Line height 48dp, state
word's baseline centred. No fill, no radius, no press state, no ripple, no
chevron: a line you cannot press is print, and print is the point. A state
change is a *re-print* — the word re-strikes in place, instantly, no
animation, no flip (a computed fact changing is struck, not performed).

**The board, in fixed order** (order never changes; a line is never added
without amending this table through §1.0.5):

| Line (name) | State words | What it reports |
|---|---|---|
| `ACCESSIBILITY` | GRANTED / MISSING | The service the seal depends on |
| `USAGE ACCESS` | GRANTED / MISSING | Foreground verification |
| `DEVICE ADMIN` | GRANTED / MISSING | The admin grant |
| `BATTERY` | GRANTED / MISSING | The battery exemption (the word reports the OS's grant, so the pair stays one pair for the whole permission family) |
| — hairline, doubled weight of space (16dp gap, no eyebrow) — | | |
| `SHORTS + REELS` | ON / OFF | The feed interceptor |
| `SOCIAL SITES` | ON / OFF | Browser social-domain blocking |
| `NOTIFICATIONS` | ON / OFF | The silencer; what it holds waits in the DIGEST (the digest itself lives off this screen — Guard reports the organ, it does not host the list) |
| `SOUND` | ON / OFF | The Float-PCM sound family |
| `THEME` | DAY / NIGHT | Reported only — theme follows the routines; this line is the board's proof that Guard *reports* the machine, it does not drive it |

**The count:** the board's one summary prints as the eyebrow's right-aligned
partner, same plate style: `3 OF 4 GRANTED` over the permission family only.
It lives here and nowhere else — the chrome `GUARD 1/4` pill is dead and
this line is its honest replacement: a count with a home, in the room it
describes, in ink.

**What the board refuses:** no descriptions under names (the old Guard's
prose — "Intercepts YouTube Shorts, Reels & TikTok feeds" — is narration;
the name *is* the description or the name is wrong); no per-line actions;
no "last checked" timestamp theatre — the board is re-struck from live state
on every entry to the screen, and a MISSING that is discovered prints as
MISSING, never as a stale GRANTED.

## 3.4 The one interactive thing: the FIX line

- **Exists only in lack.** If any permission line reads MISSING, one line
  appears under the board. If none does, there is no line and Guard contains
  **zero** interactive elements — a complete back, fully printed.
- **Form:** one full-width key, 48dp tall, radius 8 (it is a key, so it
  obeys key law), ink fill `#252323` (night: control fill `#4A423C`), word
  in porcelain/cream, Sora Bold 15sp, +0.5 — the button-word style, because
  this word carries an act.
- **Exact text:** `FIX — ACCESSIBILITY` — the verb, an em dash, the name of
  the **first** MISSING line in board order. One lack at a time, in the
  order the board prints them. On return from the Android pane, the board
  re-strikes; if another lack remains, the line re-prints for that one.
  The back has one moving part; it moves one step at a time.
- **Colour:** ink, never orange. FIX commits nothing inside the product —
  it escorts him to the OS and back. Orange on the back would spend the
  app's one COMMIT signal on a trip to Settings, and the back would start
  selling. (This supersedes, in this branch, the wave-1 consumer demand for
  an orange FIX: that demand belonged to a Guard that was a settings page
  with a hero. On a back panel, the hero is the plate.)
- **Behaviour:** answers on DOWN; opens the exact settings pane for the
  named grant — never a generic Settings home, never a permissions list he
  must hunt. ARM budget note: FIX is not on the arm path; the pre-flight
  duty (never spend his one slide on a dead seal) belongs to the Deck's
  side of the wall, and this line is the repair bench it points to, not a
  replacement for that gate.

## 3.5 The spec plate — exact text, exact setting

After the board (and the FIX line, when present): 32dp break, one 1dp
hairline at full content width (350dp at reference), 16dp, then the plate.
The plate is **not a card**: no fill, no border, no radius — print directly
on the ground (day `#E4DFDA` / night staircase ground). Plate body set in
**Anonymous Pro Regular 10sp, tracking +1.2, lineHeight 16sp, UPPERCASE,
secondary ink** (day `#5F5856` / night text tier 2); lines 1 and 2 in
primary ink (day `#252323` / night cream tier 1). *Type note, flagged to
Set in §4:* the plate is factory print, not interface label — at the plate
style's +2.0 tracking a 60-character spec line cannot fit 350dp, so the
plate takes the ladder's 10sp rung at print tracking instead of inventing a
seventh size. No orange anywhere on the plate. No line wraps; each line
below was counted against the 350dp measure at this setting.

```
MONOLITH ML-01
UNIT Nº 01 · BUILT FOR ONE USER · NOT FOR SALE
WHEEL SETS TIME · SLIDE ARMS · THE HOLD BREAKS
HOLD: 60 SECONDS, BANKED EVERY 15 · ONE BREAK A WEEK
PEEK: 2 MINUTES, THEN SHUT AGAIN
COLOUR IS A VERB: ORANGE = COMMIT · INK = SHUT · GREY = PEEK · PORCELAIN = OPEN
ROUTINES: SET BY HAND ON SHIELD · ~~FIRED AS SET~~ (STRUCK — Hale W-11, marked by the issue-9 cell under Critic C-10: returns only when Wache F1–F5 land in the same build AND a live fire is re-verified)
SITES: KEPT WITH APPS ON SHIELD · DATA: ON THIS PHONE ONLY
STUDY RECORD: IN YPT · SESSION RECORD: THE LEDGER
SOUND: FLOAT-PCM, 4 PARTIALS · POWER: YOUR PHONE
```

Line-by-line discipline: line 1 is the model; line 2 is the unit and the
built-for line — `Nº 01` never increments, never localises, and there is no
settings toggle, account, or SKU anywhere behind it; lines 3–7 are the
mechanism's specification, each one *literally true of the shipped build* —
if peek becomes configurable, if banking changes, if sites move, the line
is reprinted in the same release, because a false plate is worse than no
plate; line 8 points at the two records and refuses both (this back keeps
no numbers — no NEET countdown and no TODAY total may ever print here; the
war line owns them, once, in chrome); line 9 is the works list, the way a
manufacturer closes a back panel. The plate carries no count, no state, no
date: it is identical on day 1 and day 100, in day mode and night, whether
the board above it is whole or broken. State lives on the board; identity
lives on the plate; the two never trade jobs.

## 3.6 The discipline — what keeps it a plate and not a settings page in costume

1. **Guard changes nothing.** No switch, sled, toggle, field, or list on
   this screen alters any state inside the app. The one exception is FIX,
   which alters nothing either — it leaves. Any proposal that begins "a
   small control on Guard…" is refused by this sentence and relocated:
   switches and lists go to SHIELD (their working room), commits go to
   DECK or TASKS, and what fits nowhere dies.
2. **Sites live on Shield in this branch too.** The site list is a working
   list (ADD / CUT / sleds) and working lists live with the apps they sit
   beside. Guard keeps no list but the board. This is the load-bearing
   refusal: the old Guard was a settings page precisely because it hosted
   the site list and the switch farm; remove the farm and the list, print
   their *states* as the board, and what remains cannot be mistaken for
   settings.
3. **No prose.** Nothing on Guard is a sentence except plate lines. If a
   board line needs explaining, its name is wrong — rename the line
   (through §1.0.5), never annotate it.
4. **No heroes.** No 20sp permission hero, no big count, no illustration
   of safety. The largest type on the screen is a 15sp state word. A back
   panel does not have a hero; it has print.
5. **No freshness theatre.** No timestamps, no "last synced," no pulsing
   dot. The board is struck on entry from live state and is exactly as
   true as that strike; the plate never changes with state at all.
6. **The word SETTINGS never prints** — not as a title, a row, or a FIX
   destination label in our own copy. The moment the screen calls itself
   settings, it becomes settings.
7. **Scroll discipline:** the plate is always the last thing and always
   reachable; if board + plate fit one screenful on the reference device,
   the screen does not scroll at all — a back you must scroll is a long
   settings page wearing the plate at its foot like a fig leaf, and the
   board's line count (9) was chosen so it fits.
8. **Acceptance check:** screenshot Guard. Cover the FIX line. What
   remains must be indistinguishable in kind from a photograph of a
   printed back panel: names, states, specification, unit number — and
   nothing that invites a finger. If any element outside the FIX line
   looks pressable, the branch has failed and the element moves or dies.
