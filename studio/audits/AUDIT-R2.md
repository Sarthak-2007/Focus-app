# Focus-app — Brutal Audit, Round 2 (new issues only)

24 fresh angles that round 1 did not take. Every agent was given all 251 round-1 titles and ordered to drop repeats; a title-similarity sweep afterwards flagged only one borderline instance (a different store ignoring commit()'s result), kept as a distinct instance.

**Totals: 107 new findings — 11 critical, 48 high, 35 medium, 13 low. Running total across both rounds: 358.**

## The worst new charges

- **The weekly emergency token is infinitely renewable.** It is keyed to the week anchor of the wall clock — set the phone date to any other week and you have a fresh, unspent token. The 1-per-week law is a calendar setting away from fiction.
- **Clock tampering forges and erases shield verdicts.** The shield-gap latch is pure wall-clock: an 11-second forward jump permanently latches 'shield was off' on a healthy session; a rollback erases a real gap. A jump into a future routine window materialises a fake session that can be stamped MISSED before the window ever happens.
- **A reboot resurrects peeks.** The persisted 2-minute peek lease stores a monotonic timestamp with no boot identity — after a reboot it can read as valid for up to the previous boot's entire uptime.
- **Fresh installs attack the user.** First launch auto-starts a live blocking routine session: the seeded routines cover ~21 hours a day and are all enabled.
- **Existing installs can never update in place.** Per-machine debug signing plus total backup/transfer exclusion means the first real update wipes everything.
- **'BATTERY: GRANTED' is false assurance on most phones.** There is no OEM autostart layer at all — on Xiaomi/Oppo/Vivo/Huawei, autostart (not the AOSP battery exemption the app checks) gates every restart.
- **Clear-data is total and undetectable**, and a manual relaunch after force-stop never restarts the shield for the restored session — protection dies silently both ways.
- **A known-vulnerable HTTP stack is one uncomment away.** The catalog pins OkHttp 4.10.0, whose Okio 3.0.0 carries CVE-2023-3635 (remote gzip DoS, CVSS 7.5); the deps are commented out but deliberately kept 'easy to add back'. Zero supply-chain controls anywhere: no locking, no verification metadata, no Dependabot.
- **The site blocker is a substring guess.** It does a raw `contains` on URL-bar text — Google Translate's proxy (instagram-com.translate.goog) and similar rewrites sail straight through, as the auditor demonstrated against the shipped matcher.
- **Production failures are invisible.** There is no logging and no crash reporting anywhere in the app (zero Log calls in main sources) — every failure mode in both audits fails silently, for the user and for the developer.
